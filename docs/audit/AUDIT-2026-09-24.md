## Measured cost of the work inside the tap callback

Per call, release build, warm:

| Work | Cost |
| --- | --- |
| ASCII-capable layout lookup + `UCKeyTranslate` | 0.4 µs |
| `NSWorkspace.frontmostApplication` | 0.1 µs |
| `resolvingSymlinksInPath()` on the frontmost executable | 7.0 µs |
| `resolvingSymlinksInPath()` per path target | 7.7 µs |
| Full match against a two-entry list | 26.0 µs |

The keyboard-layout lookup is cheap and needs no cache. The symlink resolution is filesystem
I/O and is the only blocking call on the path. → HO-03

## Findings

| ID | Where | Finding | Level | Fix risk | Plan |
| --- | --- | --- | --- | --- | --- |
| HO-01 | `Sources/Store.swift:117` | `delay` is read from preferences without validation. A corrupt or wrongly typed value yields `0` (the hold ends instantly, ⌘Q is effectively unguarded) or an arbitrarily large number (⌘Q is swallowed for minutes). | critical | low | Clamp to 0.3–3.0 on read and on write; keep the key, the type and the 1.0 default. |
| HO-02 | `Sources/HoldOnApp.swift:88`, `KeyGuard.swift:39` | A dead tap is never noticed. The 5 s poll only checks Accessibility; `CGEvent.tapIsEnabled` is never read and `isRunning` is never used. | HO-03 | `Sources/Store.swift:96` | Filesystem I/O inside the tap callback: `resolvingSymlinksInPath()` runs for the frontmost app and for every path target on each guarded keystroke. A target on a stalled network or removable volume blocks the callback, delaying input and risking a tap timeout. | medium | low | Resolve target paths when the list changes, resolve the frontmost executable once per pid. |
| HO-04 | `Sources/KeyGuard.swift:104` | After a hold fires, the key-up of *any* guarded key is dropped, including ⌘W when the ⌘W guard is off and its key-down was passed through. ## Checked and found sound

- **Tap disable events.** `tapDisabledByTimeout` and `tapDisabledByUserInput` re-enable the tap in the callback itself.
- **Replay loop.** The replayed keystroke carries a marker in `eventSourceUserData`, and both the key-down and key-up paths check it before doing anything, so the tap cannot re-enter itself.
- **Focus.** The HUD window is borderless, `ignoresMouseEvents`, ordered with `orderFrontRegardless` and never made key, so it cannot take focus or swallow input. `canJoinAllSpaces` and `fullScreenAuxiliary` make it correct over full-screen apps and on secondary displays.
- **Auto-repeat.** A held ⌘Q repeats key-downs; all of them are swallowed until ⌘ is released.
- **Releasing ⌘ before Q, or Q before ⌘.** Both cancel the hold and hide the HUD.
- **Layout switching.** Shortcuts resolve through the ASCII-capable layout, so a Russian or Greek layout keeps ⌘Q guarded; the lookup is re-read per keystroke, so switching layouts mid-session is picked up at once. A missing layout falls back to the US key codes 12 and 13.
- **Permission revoked.** `AXIsProcessTrusted` is re-read every 5 s; the guard stops, the icon turns into a warning triangle and the settings window shows the Allow row.
- **Preferences robustness.** A corrupt `targets` blob, an unknown `scope` and unexpected types for the booleans all fall back to safe defaults. Only `delay` is unguarded (HO-01).
- **Concurrency.** The tap is attached to the main run loop and the callback asserts main-actor isolation; settings and the layout API are only touched there.
- **Repository hygiene.** No secrets, keys, tokens or personal paths in the tracked files or in any commit message. No session links in the history. Two commits carry a plain `Co-Authored-By: Claude` line, which is what was asked for.
- **Licensing.** `NOTICE` reproduces the SlowQuit MIT notice verbatim and ships inside the app bundle; every derived source file carries the dual SPDX header; the README states both licences.
- **Build and signing.** Hardened runtime is on, no entitlements are requested (the event tap needs none; Accessibility is granted through TCC), the universal binary is signed as one and verifies.

## Needs the owner's decision

1. **Version and release.** `main` has moved well past the published 1.0.0: the menu bar and the settings window were rewritten, and launch behaviour changed. The next release wants `CFBundleShortVersionString` 1.1.0, `CFBundleVersion` 2, a `v1.1.0` tag, fresh artifacts and a cask bump. I changed none of these, since the cask and the published DMG depend on them.
2. **Notarization.** Needs a Developer ID Application certificate in your keychain, signing with `--timestamp`, an App Store Connect API key or app-specific password stored with `xcrun notarytool store-credentials`, then `xcrun notarytool submit dist/HoldOn-<v>.dmg --keychain-profile <name> --wait` and `xcrun stapler staple`. It also means a Makefile change. Tell me to do it and I will; I have submitted nothing.
3. **Non-activating panels.** When a utility shows a panel that takes key focus without activating its app (Spotlight-like launchers), `frontmostApplication` still reports the app underneath. The HUD then names that app, while the replayed ⌘Q reaches whichever window holds key focus. Correct handling needs the key window's owner, which costs a window-list query per keystroke. Documented, not changed.
4. **Secure Input.** While a password field holds secure input, the session tap receives nothing, so ⌘Q is unguarded for that moment. This is a macOS guarantee and cannot be worked around; it deserves a line in the README if you want users to know.
5. **Name matching for path targets.** `/usr/bin/java` deliberately matches any binary named `java`. It is what makes JDK copies work, and it is also broader than the literal path. Keep or narrow.

## Suggestions for later

- Show the tap's health in the menu, so "running but not guarding" can never look identical to "guarding".
- Tests for the preferences round-trip, which currently needs `UserDefaults.standard`; an injectable store would make it reachable.
- A `notarize` target once a Developer ID exists, and a `dist` guard that refuses to package when the Info.plist version has no matching tag.
- `make dist` is not byte-reproducible: `ditto` and `hdiutil` record timestamps, so every build has a new checksum. Always take the cask's sha256 from the artifact you upload.
